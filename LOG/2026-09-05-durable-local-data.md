# 9b577c4 — Version 5 becomes the floor below which device data may not be destroyed

Date: 2026-09-05 11:06

Taskflow destroyed every task on the device whenever its database shape changed. The user captured
this on 2026-09-01 at the moment an install prompt warned it would delete the app's data, and their
point was the one that decided it: the goal is a state where their tasks live in Taskflow stably
enough to actually use it, which is a requirement rather than a nice-to-have. The justification
written into the code — that a wipe is acceptable while there are no real users — was retired by
them becoming one, so the decision needed remaking rather than merely honouring.

The bite was in a fact read during planning: there was no `app/schemas` folder, and Room writes and
tests migrations against a *recorded* schema. So no migration could have been written even if
someone had wanted one. Three of the four version bumps had landed in a single run that closed on
2026-09-02, each emptying the device.

Nothing needed migrating, because v5 was already current. The work was building the floor so the
next schema change cannot quietly fall back to a wipe: schemas are now exported, the blanket
`fallbackToDestructiveMigration(dropAllTables = true)` is replaced by
`fallbackToDestructiveMigrationFrom(dropAllTables = true, 1, 2, 3, 4)`, and the comment beside it
states the new rule rather than the retired justification. Writing migrations for versions 1 to 4
was refused at planning — no data exists at those versions that anyone wants.

Scope was settled with the user on 2026-09-03 as surviving app **upgrades**. Surviving a reinstall
or a lost phone is a different mechanism and stays where it already sits: Android Auto Backup and
the JSON export, neither of which has been tested.

Files touched:
- `app/build.gradle.kts` — ksp `room.schemaLocation` argument, and the androidTest source set's
  assets pointed at `app/schemas` so `MigrationTestHelper` can read them
- `app/src/main/java/com/example/taskflow/data/local/TaskflowDatabase.kt` — `exportSchema = true`,
  the narrowed destructive fallback, and the rewritten comment
- `app/src/androidTest/java/com/example/taskflow/data/local/MigrationTest.kt` — new; creates a v5
  database, writes a task, reopens it and asserts the task survived
- `app/schemas/com.example.taskflow.data.local.TaskflowDatabase/5.json` — generated by the build
