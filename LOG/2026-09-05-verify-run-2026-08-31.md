# [HASH] — Twelve unchecked areas of the 2026-08-31 run driven on a real phone; two failed, one unreachable

Nineteen work items shipped in that run and three were ever checked on a device. Everything else was
written, compiled once, and never exercised — each item's LOG entry ending in an UNCONFIRMED tick naming
its own check, twelve of them scattered across files nothing reads on a schedule. This audit collected
them and ran them.

It was reshaped from a `[user]` walkthrough at planning, on Claude's recommendation and Alex's
agreement, after a capability check found what nobody had checked before: TOOLS.md said Claude could not
compile, test or install this app — true of Gradle, never true of the device. Almost every observable
here is a pass/fail state check rather than a judgement, and those are Claude's to run. Splitting it into
twelve items was refused too: the checks share one app session and one setup, so twelve items would pay
that cost twelve times.

**The red flag it carried, and how the design held.** Driving the phone means Claude sees real tasks in
screenshots, and this repository is public — a committed screenshot would publish whatever was on screen,
permanently. The flag was cleared at planning by designing that out rather than by accepting it, and the
design was honoured: every screenshot stayed in the session scratchpad, outside the repository and
self-clearing; the database was never copied off the phone; TEST-LOG records verdicts and never task
content. Test data created during the drive was removed afterwards and the two settings touched were put
back.

**What passed.** Recurring tasks, including the 30-day cap holding exactly and a completed instance
leaving tomorrow's untouched. Drag-reorder, surviving a relaunch. Drag between screens, taking the new
slot's date across two page turns. The cut drag-target and its clipboard round-trip. Date format
reaching every surface. Empty states. Focus on a Project — all four of its behaviours, including a task
captured while focused filing into the focused Project, and a relaunch opening unfocused. And JSON export
and import, run for the first time ever: the export carries completion state and recurrence, the
destructive import warns first and names the non-destructive alternative, and everything round-tripped.

**What failed.** Search covers only active tasks: an empty query lists active tasks with no date headers,
typing narrows to active matches, and a task completed minutes earlier appeared in neither — against a
SPEC section whose whole argument is that one surface removes the "am I looking in the right place?"
guess. And the edit dialogue has no outliner at all: the Task field is a single line, Enter does nothing,
and three typed lines ran together into one title.

**The second failure is the largest thing this audit found**, because of what it takes with it. With no
outliner there is no way to create a subtask anywhere in the app, so subtasks, the parent's
expand/collapse rollup, the completion roll-up and the promote target are unreachable rather than merely
untested — recorded as blocked, not failed, since nothing could exercise them. It also blocks half of
cut-and-paste: a childless task round-trips, but the indented parent-with-children block SPEC describes
cannot be produced.

Five checks were left unrun for stated reasons rather than for want of time, and are collected in their
own capture rather than lost with the session.
