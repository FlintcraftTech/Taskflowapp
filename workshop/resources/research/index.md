# Research index

One line per finding: the subject it settles, enough of the finding to decide
whether to open it, and the filename at the end.

- Google Play developer account, organization versus personal — both types can sell subscriptions, so a registered business is not required to take money; what separates them is identity and paperwork, and the account type cannot be switched afterwards. Personal needs a government ID and puts the individual's own legal name and home address on customer receipts; organization needs a D-U-N-S number (free, up to 30 days), incorporation documents, proof of a physical address that is not a registered agent's, an authorised representative named on the registration, plus a public organization phone number and website. Costs and Google's revenue share are identical on both — google-play-organization-account-requirements.md
- Where Taskflow's paid tier could run — Supabase does both jobs in one product (Postgres plus an OAuth 2.1 Server documented for authenticating your own users to your own MCP server, with dynamic client registration as a setting), free while building but free projects pause after a week of inactivity, $25/month for Pro; Cloudflare Workers is more purpose-built for the MCP half via `workers-oauth-provider` at $5/month base but leaves the sync store and user accounts to be assembled. Also carries the finding that dynamic client registration was demoted to a fallback by the MCP spec of 2025-11-25 in favour of Client ID Metadata Documents, which ages [0020-remote-mcp-server]'s stated auth mechanism — paid-tier-backend-and-mcp-hosting.md
- How a Claude custom connector authenticates to a remote MCP server — the connector surface accepts `oauth_dcr`, `oauth_cimd`, `oauth_anthropic_creds`, `custom_connection`, `static_headers` and `none`, with the two OAuth discovery flows working out of the box; the consumer add-connector flow asks the user only for a server URL (OAuth client ID/secret sit behind Advanced settings) and there is no consumer field for pasting an API key, while published guidance explicitly warns against credentials in the URL because it leaks through logs, history and screenshots — which together leave OAuth as the only per-user shape available — claude-custom-connector-auth-options.md
- Where the bug-report address can live — email is always a separate provider from the registrar, because Netlify offers no email service at all, so MX records can point at a mail provider while the domain sits anywhere and email never waits on a transfer; forwarding (Cloudflare free but needs the nameservers, ImprovMX free via MX records only) receives but cannot send, and sending needs a real mailbox — Google Workspace $84/year against GoDaddy's $167.40 and bare mailboxes at £10–20; also settles that a domain transfers at any time rather than at renewal, blocked only by ICANN's 60-day locks, and adds a year rather than forfeiting one. Prices in it go stale fast — domain-email-hosting-for-the-bug-report-address.md
- Supabase Row Level Security, and whether a remote MCP server must bypass it — the publishable key that ships in the Android app is safe to expose only because RLS checks the caller's token against each table's policies, so a table with RLS off or a `using (true)` policy is public to anyone who reads the key out of the APK; the per-user shape is `user_id = auth.uid()` scoped `TO authenticated`, with a silent failure mode where a no-session `auth.uid()` is null and a carelessly phrased policy widens to every row. Settles that an Edge Function can run in a mode where the platform validates the caller's JWT and hands it a client already RLS-scoped to that user, so the MCP server does not have to use the RLS-bypassing secret key. Also records that `sb_publishable_`/`sb_secret_` have replaced the anon and service_role key names — supabase-rls-and-edge-function-identity.md
- Sharing a day's tasks from Android — share-sheet targets are filtered by MIME type, so PNG and PDF are equally reachable and compatibility does not decide it; what differs is arrival behaviour (PNG renders inline in a chat, PDF opens as an attachment), which favours PNG for a short read-once day summary; also settles that Markdown must be shared under `text/plain`, since `text/markdown` is declared by almost no Android app and produces a near-empty share sheet — android-share-format-png-vs-pdf.md
